A walkthrough follows **one concrete case from start to finish** and shows what
each component does at every step: which HTTP call the worker makes, what the
engine checks, what PostgreSQL records and what happens when something fails
halfway.

## The running example

Every walkthrough uses the same support case so that the pieces connect:

- **Alice** (customer `C-42`) writes: *"My parcel never arrived"* (order `5531`).
- A `triage` **agent** node reads her record from a **CRM tool server**
  (`crm/get_customer`, a read), opens a ticket (`crm/create_ticket`, a write),
  and may refund her €89 — either through an **approval-required** tool
  (`crm/refund`) or by **delegating** to a `refund_payout` process.
- `refund_payout` pays through a **third-party payments worker** built with the
  Java SDK.

The names `crm`, `refund_payout` and `payments.payout` are illustrations; the
mechanics are those of the engine and the first-party worker.
